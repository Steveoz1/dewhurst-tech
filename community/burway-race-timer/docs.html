What the Race Timer is

A timing system for head races and time trials, run on phones. Crews start one at a time and race the clock: a starter taps START as each crew crosses the start line, a finisher taps FINISH as it crosses the finish, and race time = finish − start. Results update live.

  • Two independent copies, A and B. Each has its own starter and finisher on their own phones. A is the official record and the only one the public sees; B is the check copy. Race Adjudication compares them.
  • Every race is kept separately. Each race has its own crews, times, tap log, issues and results, and its own links. A tap made on one race's page can only ever go to that race.
  • Works without signal. A tap is stored on the phone the instant it's made and sent when signal returns. The dot at the top right shows All saved (green), Sending… (amber) or Offline (red).
  • One clock. Every phone's time is corrected to the race database's clock, so the start and finish phones agree even if their own clocks don't.
  • Nothing is ever lost. Undo, corrections and swaps add a record; the original tap stays in the log.

Setting up a race

  1. Races page (Community Support › Burway Rowing Club Race Timer › Races). Either + New race (empty), or ⋯ › Duplicate on an earlier race to reuse its crews, divisions, event combinations, handicaps and details. Duplicate never copies times, taps, statuses, notes, penalties or issues, and the new race starts as Draft with results Hidden.
  2. Race Setup: title, short name (for the top bar), date, first start time, location, course, notes for officials. The race ID goes into every link and can't be changed once the race is created — e.g. 2026-11-07-training.
  3. Divisions: how many (1–9) and each one's start time; first boating time is optional. Crews with no boating time of their own use their division's.
  4. Crews: open the race menu › Race Configuration › Import CSV. Columns: Bow#, Event, Crew Name, Club, Division. Or add crews one at a time. Withdraw a crew with its Status — crews are never deleted.
  5. Handicaps: race menu › Handicap Configuration — group events that race each other and give each its handicap in seconds.
  6. Set Live on Race Setup when you're ready to time. It refuses until there's a title, a date, a division start time and at least one crew, and says which is missing.

Sending the links

Race menu › Share links gives every link for the race, each with Copy: Starter A, Starter B, Finisher A, Finisher B, Results (public) and the race menu.

  • Send each official only their own link. A Starter B link opens the Starter page already set to B for that race.
  • The short link (…/r/<race-id>/starter-b) is easier to type. The long link always works and is the one to bookmark or Add to Home Screen.
  • Send the Results link to anyone. Until you switch results to Public, it shows "Results will be published here on race day".
  • Never send Race Setup or the Races page — they're for race admins only.

Phone checklist — before the first crew

Do this with signal, ideally the evening before and again on the morning.

Starter

  • Crews are listed in bow-number order; the next to start is highlighted. The list never moves by itself — only you scroll. Type a bow number in the jump box to go straight to it.
  • One finger, one tap on START as the crew crosses the line. The row turns green with Undo straight away. If it doesn't, the tap didn't count (a sliding finger counts as a scroll).
  • Undo works for 30 seconds without a question; after that it asks first. It's greyed for 2 seconds after a tap so a double tap can't undo it.
  • ⚑ next to Undo flags the crew for the race admin to look at — one tap, no questions. ⋯ has Mark DNS, Swap start time (only while the dot is green) and Add note.
  • Crews can start out of order. Tapping START on a crew that already has a start asks before replacing it.

Finisher

  • Every crew has a FINISH button from the beginning — finish a crew even if its start hasn't reached your phone yet; the race time appears when it does.
  • One finger, one tap as the bow crosses the line. The row stays where it is, turns green and shows the finish and race time.
  • Two or three crews crossing together: tap each one in turn, calmly — each tap gets its own time.
  • Undo, ⚑ and ⋯ work as on the Starter page; ⋯ has Mark DNF / DSQ and Swap finish time.

Race-day rules

  • Nobody signs out on race day. If a red banner appears, tell the race admin and keep the paper sheet going.
  • If the dot shows "N waiting" for more than a minute while there's signal: airplane mode on, then off. Don't reload a page showing "waiting".
  • Only use Swap while the dot is green.
  • Log anything that happens — crew changes, problems — on Updates / Issues rather than on paper.
  • Nothing is published to the website on a day a race is being timed.

Updates / Issues

Race menu › Updates / Issues. Log a crew change, a system problem or anything else as it comes in: category, bow number (optional), what happened, status (Open / In progress / Resolved). Shared live between officials' phones and works without signal. Every change is kept with who and when. An open issue on a crew shows Check on public Results until it's resolved.

Race Adjudication

Two independent sets of times: A (official, public) and B (the check). The page compares them for every crew and lists any that disagree under Needs a look. You decide which is right.

  • A crew needs a look when: starts or finishes differ by more than 2.0 s; one copy has a time the other doesn't; the statuses differ; someone flagged it; A has it as DNF or DSQ; it has an open issue; a finish is earlier than its start; or a finish has no start in A or B. The full list is on the page.
  • If A is right: Resolve (with an optional note). If A is wrong: Review › change A — usually Use B's start / finish, or type the right time — with a reason. Every change is added to the crew's tap list; nothing is deleted.
  • A crew is done when it's no longer under Needs a look. If its times change afterwards it comes back, marked "changed since resolved".
  • Public Results show Check only for flags, DNF/DSQ not yet resolved and open issues — never for A/B differences.

After the race

TV in the clubhouse: open Results signed out and set Cycle through pages? to On — pages change every 10 seconds, with the start/finish lists and the river.

Trying it out — a test race

About 30 minutes with four phones (A starter, A finisher, B starter, B finisher) and a laptop for the race admin.

Troubleshooting

"This race link isn't valid"The race was deleted or the link is mistyped. Ask the race admin for a new link.
"Timing is closed for this race"The race isn't Live (Draft, Finished or Archived). The race admin sets it Live on Race Setup.
Yellow line about the race dateThe race is dated another day — check you have this week's link.
Dot red "Offline · N waiting"No signal. Keep tapping; the taps are on the phone and send when signal returns. Don't reload.
Dot amber "N waiting" for over a minute with signalAirplane mode on, then off.
Red "Server refused a tap" bannerTell the race admin; don't sign out; keep the paper sheet going. Usually the race isn't Live or the wrong login is in use.
Blank page with no signalThe phone has never opened that page. Open every page once with signal beforehand.
"Can't reach the race database"Check the signal. If other phones are fine, use try safe mode in the banner (no on-phone database copy for 12 hours).
Opens with no crews and "Offline" on an iPad/iPhoneSettings › Apps › Safari › Advanced › Website Data › search dewhurst › swipe left › Delete. Reopen and sign in.
"clock not checked" under the clockKeep the page open with signal; it checks on opening and every 5 minutes. Tap the dot › Check now.
A B phone shows ANew or cleared phones start on A. Open your B link again, or tap B at the top.

Managing Firebase (Admin only)

The race data and the logins live in Google Firebase, project burway-sbh-2026. Use a laptop. No passwords are written here — keep them in your password manager.

Signing in

https://console.firebase.google.com → sign in with the Google account that owns the project → open burway-sbh-2026.

Logins (Authentication › Users)

  • Add a login: Add user → email (e.g. sbh-raceadmin@dewhurst.tech; it needn't be a real mailbox) → password → Add user. A new RaceAdmin or other role also needs its email adding to the security rules before it can do anything.
  • Change a password: "Reset password" in the user's ⋮ menu sends an email, so it only works if the address is a real mailbox. Otherwise: ⋮ › Delete account, then Add user again with the same email and the new password. Nothing in the race data changes — permissions follow the email address.
  • Stop a login working: ⋮ → Disable account. Do this for Starter and Finisher after a big race if their passwords were shared widely.
  • Self sign-up must stay off: Authentication › Settings › User actions › Enable create (sign-up) and Enable delete both unticked; Email enumeration protection on.

Security rules (Firestore Database › Rules)

  • The rules decide who can read and write what. The current rules box is kept in Rowing\Burway Race Timer\Firebase rules\ on Steve's computer.
  • To change them: open the rules file → copy all of it → in the console Rules tab, click in the editor, Ctrl+A, paste → Publish. They take about a minute.
  • Never publish rules on a day a race is being timed.

Plan, usage and cost

  • The project is on Blaze (pay as you go): the free daily allowance applies first; beyond it, about $0.03 per 100,000 reads. Usage: Firestore Database › Usage.
  • Keep a budget alert (e.g. £10): Google Cloud console › Billing › Budgets & alerts. It emails you; it doesn't stop anything.

The web key

Google Cloud console (https://console.cloud.google.com) › project burway-sbh-2026 › APIs & Services › Credentials › Browser key › Application restrictions: Websites — https://www.dewhurst.tech/* and https://dewhurst.tech/*. Leave it like that; it stops other websites using the project.

Looking at the data

Firestore Database › Data. Each race is under races › <race-id> with config, timings, taps and clocks inside. Look, don't edit — change data through the Race Timer pages so it's logged.

Deleting the original SBH 2026 data (later)

The 24 Oct race was copied into race sbh-2026; the original top-level config, timings and taps are kept read-only until you decide (not before 30 Nov 2026). Then: make sure you have the export file, and in Firestore › Data delete those three top-level collections (⋮ › Delete collection). The tap log can only be deleted here, never from the website.
